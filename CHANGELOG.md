## 2026-10-28 morning: DocumentsUI shows its roots
- Telegram (corpus) gets further, still not up. (2) `HostCompat`: `Compatibility.isChangeEnabled` follows the build\'s compat change list (`etc/compatconfig`, staged by `collect-android-root.sh`) and the app\'s target SDK instead of enabling every change (Telegram, target 23, died on the Android 12 `PendingIntent` mutability check). Open: `LaunchActivity.onResume` NPE (a view field is null), and a native abort `libpthread.c:497 default_pthread_mutex_init: no such default initializer` from the bionic pthread wrapper.
- Binder calling uid fixed for oneway calls: the kernel gives a oneway transaction no calling pid, so `Binder.getCallingUid()` fell back to the Linux uid. Every request now carries the sender's Android uid as the work source in its interface-token header (`ShadowHostRealParcel.writeInterfaceToken`), and `ShadowHostRealBinder.getCallingUid` reads `Binder.getCallingWorkSourceUid()` when the pid is 0. Calls from the hub JVM report the system uid 1000 (`HubClient.hubPid`). The uid assertion of the oneway callback in `hub-services` is back (the server's app uid). Still the Linux uid: callers the hub does not know and that send no work source (native services).
- Nextcloud starts (corpus): an app's own Conscrypt is outside the sandbox (system class loader), which has a second `NativeLoader` copy with unbound natives, so the shim registers the NativeLoader natives on that copy too (`runtime_shim.c`); and the APK is on the JVM class path next to `classes.jar`, so `getResourceAsStream` finds the java resources the conversion drops (`conscrypt.properties`). Its provider no longer fails, so DocumentsUI's 20 s first-load stall from it should be gone (not rechecked).
- Storage volumes as planned: per-instance `/storage` in the XDG data dir (`~/.local/share/apklayer/0/storage/emulated/0` is the sdcard); the storage service lists Internal storage, Home and Linux root. `tests/vm/files.sh` lists all three through the provider (3 roots; 63 entries in Home, 23 in `/`).
- Opening a file in another app: the hub now grants the target app the content uris of an intent that carries FLAG_GRANT_READ/WRITE_URI_PERMISSION, if the sender owns the provider, holds its permission or holds a grant (`HubProviders.grantFromIntent`, called from `HubActivities.start`, as the activity manager does). New test `tests/vm/view.sh` (privileged sender, unprivileged viewer `hello-reader`) passes.

- Home lists in DocumentsUI. The cause of the empty list was the `ConcurrentModificationException` from `ArrayList` (removing the last element in a for-each): the loop workaround only hid it and `onLoadFinished` stayed aborted, so no second directory ever loaded. `JdkPatch` now gives `ArrayList$Itr` Android's `limit` semantics (PATCHES.md); the main-loop workaround is gone.

Android native-buffer import/sync and hardware presentation remain separate required steps, not claimed by this checkpoint.
