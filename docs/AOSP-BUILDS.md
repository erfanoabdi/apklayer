# Building in the LineageOS tree (how-to; the dated log of every build is in ../CHANGELOG.md, section "Build log")

Authorization (user, 2026-10-27): build what is needed in `~/los24` (OrbStack VM `ubuntu22-x86`) autonomously. Rules that never change:
- Only incremental builds of `gsi_arm64 userdebug` in the existing `out/` (115 GB, device build in `out/target/product/generic_arm64`):
  `cd ~/los24 && source build/envsetup.sh && breakfast gsi_arm64 userdebug && m <target>`.
- **Never wipe or clean `out/`**: no `rm -rf out`, `m clean`, `installclean`, no other product, no separate `OUT_DIR`, no `git clean`/`repo sync -d` that could remove it.
- Log each build in `CHANGELOG.md` ("Build log") before it runs: what, why it is necessary, command, result.
- The tree's own projects carry apklayer's edits as plain patches, `patches/aosp/<project path>/*.patch` (each project's pinned commit in its `REVISION`):
  `patches/apply aosp ~/los24` applies them, idempotently (already-applied patches are skipped). Check without writing: `git -C ~/los24/<project> apply --check -R <patch>`.
- Edit `aosp/` in this repo and run `tools/sync-aosp.sh "message"` (mirrors into `~/los24/vendor/apklayer`); modules are listed in `aosp/hals/README.md`.
- Incremental replay of one module without a graph change: `tools/lib/orb-build-module.py <module> <dir under vendor/apklayer> <Source.cpp ...>` (Vulkan: `tools/lib/orb-build-vulkan.py`),
  then install the output on the test VM (`tools/stage vulkan`, or copy from `~/apklayer-stage` to `~/android-arm64/lib64` and check the sha256). Adding a source file or
  module needs a build-graph regeneration: ask first.

Files taken from the tree: `deps/android-tree-files.lock` lists every file the route stages from the LineageOS build (the Android libraries, the framework jar,
`Robolectric_all.jar`, the Android root with APEX data, fonts, `build.prop`, platform resources): sha256, size, path on the VM, origin in `~/los24`, status (`same` or
`apklayer` = built from `vendor/apklayer`). Generated by `tools/gen/tree-files-lock.py`; the tree's identity (fingerprint, release, build date) is in its header. The binaries are
not in git (about 600 MB): the lock plus `tools/stage libs`, `tools/stage root` and the build log reproduce them.
